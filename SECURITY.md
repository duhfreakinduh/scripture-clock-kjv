# Security Policy

## Reporting a vulnerability
Do not post secrets, private URLs, personal notes/prayer content, exploit details, or sensitive logs in a public issue. Use GitHub private vulnerability reporting if enabled; otherwise open only a minimal issue until a private channel is established.

## Security expectations
- Never commit provider/API tokens.
- Treat personal notes and prayer content as private.
- Do not send private user content to remote AI without explicit user action and disclosure.
- Keep Scripture text separate from generated commentary.
- Bound AI/network calls with timeouts and safe fallbacks.
- Review third-party data/CDN changes before release.
